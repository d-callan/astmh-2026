Frame up front: this talk is not "use AI for genomics." It's about what you point the AI at. The GTN is 550+ human-written, human-reviewed tutorials — and it happens to be exactly the corpus an agent needs. Humans write it; machines read it. That asymmetry is the whole talk.

The Bottleneck Isn't Sequencing Anymore

Sequencing has reached labs where analysis expertise hasn't followed.

When a new pathogen dataset lands, two bad options
  • Wait — for a workshop, a course, a collaborator with free time
  • Ask an AI — which will cheerfully produce a plausible pipeline
What "plausible" costs you

Tool versions that never existed together. A filtering step quietly dropped — the one that decides whether two isolates look like transmission. And no record of either.

The framing for this talk

An agent with no curriculum improvises. The GTN is a curriculum.

Motivation
Say out loud that the room contains both AI enthusiasts and AI skeptics, and that this talk is aimed at both. The failure mode isn't that the model refuses — it's that it answers confidently. The concrete example to speak, not read: an invented TB pipeline that skips the low-coverage/repeat-region masking step produces transmission clusters that look fine and are wrong.

What this means in practice

No scraping. No RAG pipeline to build. The curriculum is already a corpus.

The GTN
This is the pivot of the talk. Nobody designed the GTN as AI infrastructure — it's Markdown, YAML and JSON because that's how you maintain 557 tutorials with 700 volunteers across a dozen countries. The accident is that those are exactly the formats an agent ingests without help. Live-demo option: run that curl and show the JSON.

The GTN Has Rules for Agents — In the Repo

Agents may not
  • Write tutorials, news, events, or learning pathways — any learner-facing prose
  • Write your pull request descriptions, issues, or replies to reviewers
Agents may
  • Answer, analyze, distill, check, suggest, review
  • Assist on the codebase — with disclosure, and an assisted-by: commit trailer
Why — and it's a scientific argument

Most GTN contributors are not native English speakers. The community would rather have your imperfect words than a model's smooth ones — homogenized prose flattens a deliberately multi-voice curriculum, and reviewing it shifts the work onto volunteers.

Policy
This is the slide that earns trust with the skeptics — and it isn't my policy, it's the community's, written down in AGENTS.md and AI-policy.md in the repo. One line to remember

Tutorial for the method. Galaxy for the compute. History for the proof.

How
All three are available now and none require you to pick a model. Galaxy MCP works with any MCP client — Claude Code, Codex, your own script, a local model on university HPC. The Job Error Wizard is the one people underrate: it reads the real stderr, so it is grounded in the same way the GTN grounds the method.

Why a Tutorial Beats a Prompt

Four things a GTN tutorial ships that a confident paragraph doesn't.

Named input data
Pinned to a Zenodo record — you can start from the same bytes
A workflow that has run
140 of them run under CI against a real Galaxy server
Expected outputs
Something to diff your result against before you trust it
A stated rationale
Why this step, this threshold, this reference — in a human's words
The version for the skeptic in row three

You don't have to trust the agent. You can check its homework against a page anyone can read.

Why it works
Payoff slide. The fourth card is the one that can't be automated and is the reason the GTN bans AI-written tutorials — a stated rationale is only worth something if a person actually held the opinion. Tie back: Galaxy records what ran, the GTN records why it should have.

What This Does Not Fix

Wrong tutorial, confidently
Topic match is not study-design match. The agent can't know your sampling frame.
Teaching data is small on purpose
Subsampled so a workshop finishes. Your 500 isolates are not the demo set.
228 workflows still untested
"Has a workflow" is not yet the same as "is verified."
  • No GTN MCP server yet — today an agent reads the JSON API and the Markdown directly. An obvious next step, not a shipped one.
  • The GTN states plainly that it cannot offer support on anything referencing AI output — grounding doesn't transfer responsibility.

Limits
Do not skip this slide for time. In a room with real skeptics, naming the limits yourself is what makes the rest credible. The subsampled-data point is the most practically important one — it is the single most common way a tutorial-derived analysis goes wrong at real scale.

Why the gap matters more than it used to

A hole in the curriculum used to mean no workshop for your pathogen. Now it also means an agent grounding on the GTN finds nothing to ground on — and improvises instead.

The gap
This number is checkable and you should invite them to check it: every topic from the GTN JSON API, 689 materials, searching titles and tags. TB is genuinely excellent — three tutorials and real depth, because a community decided to build it. Nothing structural stopped anyone writing the malaria equivalent; nobody has. Then land the closing line, which is the hinge of the whole talk: grounding only protects you where the curriculum exists, so the coverage gap is now also an AI-reliability gap for exactly the diseases in this room.
